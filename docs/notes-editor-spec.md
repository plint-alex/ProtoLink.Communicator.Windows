# ТЗ: редактор заметок ProtoLink (Windows + Android)

> Цель: единое ожидаемое поведение без ручной проверки «на глаз» каждого бага.  
> Эталон UX: **Microsoft OneNote** (To Do / Ctrl+1), также Apple Notes / простой Notion to-do.  
> Реализация: shared `notes-editor.js` (WebView). Источник правды — этот документ + автотесты `shared/notes-editor/run-tests.mjs`.

## 1. Принципы

1. **Строка = единица формата.** Чекбокс, маркированный и нумерованный списки применяются к *текущей строке / выделенным строкам*, а не ко всему списку целиком (если выделена не вся группа).
2. **Toggle.** Повторное действие снимает формат с затронутых строк; текст остаётся.
3. **Клик по ☐** отмечает выполненным; **не** удаляет пункт и **не** снимает тип «чеклист».
4. **Панель / команда ☐** добавляет или снимает *тег чеклиста* (как OneNote To Do Tag / Ctrl+1).
5. HTML на диске совместим между Windows и Android (`ul.checkbox-list` + `input` + `label`).

## 2. Чеклист (checkbox list) — спецификация

| Действие | Ожидание |
|----------|----------|
| Курсор в обычном абзаце → ☐ | Этот абзац становится **одним** пунктом чеклиста. Соседние абзацы не трогаем. |
| Курсор в пункте `•` / `1.` → ☐ | Только этот пункт становится чеклистом (список при необходимости разбивается). |
| Курсор в пункте чеклиста → ☐ | Снимается чекбокс **только с этого пункта**; остальные пункты чеклиста остаются. Текст пункта остаётся (как обычный абзац). |
| Выделено несколько пунктов чеклиста → ☐ | Снимается чекбокс со **всех выделенных** пунктов, невыделенные не трогаем. |
| Выделено несколько обычных строк → ☐ | Каждая строка → пункт чеклиста. |
| Enter в непустом пункте | Новый пункт чеклиста ниже. Если каретка **в середине** текста — хвост после каретки переносится в новый пункт (split), не остаётся на старой строке. |
| Enter в пустом пункте | Выход из чеклиста: пустой пункт убирается, ниже обычный абзац. |
| Backspace в начале пункта (пустого или с текстом) | Снять чеклист с **этого** пункта (текст сохраняется). |
| Клик по квадрату checkbox | Toggle checked / unchecked + визуально (зачёркивание/opacity). |
| Удаление текста пункта целиком, затем Backspace | Как выход из пункта (см. выше), не «залипание» пустого checkbox. |

**Анти-баг (регресс, из‑за которого заведено ТЗ):** кнопка ☐ **не** должна снимать чекбоксы со всего `ul` при курсоре на одном пункте.

Референс: [OneNote To Do](https://support.microsoft.com/en-us/topic/create-a-to-do-checklist-in-onenote-8f745fe6-8905-be92-ba05-223c5f5987cd), Ctrl+1 / Remove Tag на строке.

## 3. Остальное форматирование (кратко)

| Функция | Поведение |
|---------|-----------|
| B / I / U / S | Toggle на выделении; active-state на панели. |
| Заголовки H1–H3 / Normal | К текущему блоку; combo/sheet синхронизируется с caret. |
| • и 1. | Список на текущей строке / выделении (browser `insertUnorderedList` / `insertOrderedList`). |
| Indent / Outdent | Tab / Shift+Tab вне таблицы; в таблице — навигация по ячейкам. |
| Ссылка | Win: Ctrl+K / кнопка → диалог URL. Android: кнопка → диалог. Только `http(s):`. |
| Ctrl+клик по ссылке (Win) | Открыть в системе. |
| Paste | Sanitize: без `script`/`style`/`img`/javascript-URL; разрешены базовые блоки/инлайн/таблица/наш checkbox-list. |
| Copy | Нормальный plain + html без лишних пустых строк. |

## 4. Типичные жалобы пользователей RTE (что обязательно покрыть тестами)

Источники: contenteditable issue catalogs, CKEditor/WebKit backspace reports, гайды по paste/undo.

1. **Paste из Word/браузера** ломает заметку (стили, `o:p`, скрипты).  
2. **Backspace** на границах блоков/списков оставляет «мусорные» пустые теги или глотает соседний блок.  
3. **Чеклист / to-do** нельзя снять с одной строки; или снимается со всего списка.  
4. **Enter** в списке не создаёт следующий пункт / не выходит из списка на пустой строке.  
5. **Курсор** прыгает после format/paste.  
6. **Undo** после format/paste ведёт себя непредсказуемо (желательно не ломать браузерный undo лишним `innerHTML=`).  
7. **Фокус** уезжает на toolbar — нельзя печатать / Ctrl+Z (у нас кнопки `Focusable=False`).  
8. **Мобильная клавиатура** (Android): format bar перекрывает caret; Enter/Backspace в чеклисте.  
9. **Ссылки**: нельзя вставить / клик редактирует вместо открытия.  
10. **Синхронизация панели** (active state) врёт или падает (у нас был `JsonDocument` dispose).

## 5. Чеклист проверки после изменений (Acceptance)

Запускать **автотесты** + короткий smoke на «Вишлист». Ручной проход только если автотест ещё не покрывает пункт.

### A. Авто (обязательно)

```bat
cd shared\notes-editor
node run-tests.mjs
```

```bat
dotnet test ProtoLink.Communicator.Windows.IntegrationTests --filter NotesEditorShellTests
```

Ожидание: все зелёные. При правках чеклиста в `run-tests.mjs` должны быть кейсы:

- [ ] toggle ☐ снимает чекбокс **только с среднего** пункта в списке из 3  
- [ ] соседние пункты остаются `ul.checkbox-list`  
- [ ] текст снятого пункта сохраняется  
- [ ] Backspace в начале пункта снимает чеклист с одного пункта  
- [ ] Enter пустой / непустой  
- [ ] paste sanitize  
- [ ] bold / link API  

### B. Smoke на заметке «Вишлист» (1–2 мин)

1. Открыть Notes → **Вишлист**.  
2. Встать курсором на **один** пункт чеклиста → ☐ → чекбокс исчез только у него.  
3. Снова ☐ на обычной строке → появился один checkbox.  
4. Клик по квадрату → checked/unchecked без удаления текста.  
5. Enter в конце пункта → новый checkbox-пункт.  
6. Enter на пустом → выход в обычный текст.  
7. Ctrl+V кусок из браузера → нет «ломаной» вёрстки, можно печатать дальше.  
8. Нет диалога Error / WebView.

### C. Регресс панели / платформы

- [ ] Win: ☐ подсвечивается только когда caret в checkbox-пункте  
- [ ] Win: после ☐ фокус остаётся в редакторе (печать сразу)  
- [ ] Android: то же с нижней format bar над IME  
- [ ] Заметка, сохранённая на Win, открывается на Android с чеклистами и наоборот
